## Required safe workflow
1. Read `docs/agent/LOW-REASONING-RUNBOOK.md`; inspect `git status --short`.
2. Run `python3 tools/validate_plan.py`, `python3 tools/agent_tasks.py doctor` and `python3 tools/agent_tasks.py next`.
3. Read only the active task card (`docs/agent/tasks/<ID>.md`) and its cited contracts. Start a task only when dependencies are complete.
4. Implement one bounded task; run real focused checks, record evidence and checkpoint; automatically select next ready safe task. On a new session, resume in-progress work, never regenerate it.
5. Task marked completed requires actual implementation + passing tests; a docs graph check alone does NOT prove a code task.

- DO NOT recreate Next.js or run create-next-app. Existing root `app/`, `public/`, `next.config.ts`, `tsconfig.json`, `eslint.config.mjs`, `package.json`, `package-lock.json` must stay until migration task.

## Architecture and security
- Next.js App Router + Hono API + BullMQ worker + installer CLI; MySQL/Drizzle, Better Auth, Zod, DB-driven RBAC. No direct DB imports in browser.
- Salt & Pepper default colors; exactly four admin sidebar groups: Dashboard, Manage Content, Manage User, Setting.
- Protected first Super Admin `admin@codelight.id` uses installer-supplied secret; force password change. NEVER commit or log any password or production secret.
- Production uses uploaded build artifacts and Node/PM2 behind aaPanel/Nginx; NOT Docker.
- Never run production restore, destructive migration, credential reset, deployment or data deletion without environment-specific authorization. Never use `git reset --hard` or `git clean -fd` as recovery.
- On ambiguous contracts or missing prerequisites, block safely and record precise reason; do not improvise privileges or schema.
